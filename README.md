# Signal Lab v5.8 — 0개 시그널 검증 및 관찰 화면 (PC·모바일 공용)

## 확인한 원인
* 이전 v5.7에서는 '90점 이상'이라고 표시했으나 9개 기술 항목 모두를 `quality.passed`의 조건으로 요구하여 사실상 **100점만 인정**했습니다. v5.8은 이를 100/100 필수 충족으로 명확하게 표기합니다. 매매 알림 및 자동 모의 진입의 기존 엄격한 게이트는 완화하지 않았습니다.
* 기존 패턴 판정은 최신 마감 **1시간봉 하나에서만** 시그널을 판정했고, 화면은 최근 2시간 기록만 보여줬습니다. 따라서 정상 분석 7,000회여도 해당 시간대에 신호가 없으면 0건일 수 있었습니다.

## 추가된 표시 (매매 신호와 철저히 분리)
* 1H 가격 구조 관찰: 최근 20봉 박스 상단/하단 접근, 4H 방향과 1H EMA20 접근. **진입/가상 매매/알림을 발생시키지 않습니다.** 5개씩 페이지 이동.
* 최근 24시간 과거에 실제 종가 확정으로 발생한 패턴 기록. 현재 주문 신호가 아니며, 당시 데이터가 완전한 독립 백테스트도 아닙니다. 5개씩 페이지 이동.
* 과거 패턴은 당시까지 마감된 4H 캔들만 사용해 미래 추세를 끌어오지 않도록 했습니다.
* `/api/results`의 `structures` 및 `history` 배열과 `/api/scan/diagnostics`의 `structureCount`, `historicalPatternCount` 로 상태를 진단할 수 있습니다.
* 가격·시세를 수신하지 못하면 후보를 만들어내지 않습니다. '시장 접근 후보'는 확정 시그널이나 승률 높은 추천이 아닙니다.
* 기존 `%LOCALAPPDATA%\SignalLab`의 PNL / 계좌 모의매매 / 텔레그램·알림 설정을 유지합니다.

## 실행
구버전의 start.bat 또는 start_mobile.bat 종료 후 새 ZIP을 **별도 폴더**에 모두 압축 해제하세요.
PC: `start.bat`; PC 및 같은 Wi-Fi 모바일: `start_mobile.bat` **하나만** 실행. PC 주소 `http://127.0.0.1:3000`.
모바일 주소는 실행 창에 표시된 PC 사설 IP를 사용합니다.

## 테스트 한계
`npm test`: 자동 테스트와 모의 API 연동 검사. 실제 거래소 연결 및 사용자의 네트워크·윈도우 알림 수신 성공은 이 환경에서 확인하지 못했습니다. 실제 최종 신호 0건이 기술 설정 탓인지 거래소 API 탓인지 정확히 확인하려면 사용자의 `/api/scan/diagnostics` 값이 필요합니다.

# Signal Lab v5.7 — 가상 진입/CLOSE Windows 알림 (PC·모바일 공용)

- **스캔 후보 목록**: 현재 발견된 확정 패턴 / 롱·숏 / 검증 통과 필터에 대해 **5건씩 페이지 나누기**. 페이지 번호·이전·다음 버튼, 전체 건수·현재 범위 표시. 필터 변경 시 첫 페이지로 이동하고 데이터 변경으로 현재 페이지가 사라지면 마지막 유효 페이지로 보정합니다.

- **PC·휴대폰 동일 화면과 기록**: Windows에서는 `start.bat`, 신뢰하는 같은 Wi-Fi 모바일 접속에서는 **PC에서 `start_mobile.bat`만** 실행합니다. 두 실행 파일을 동시에 열면 포트 충돌 및 기록 잠금으로 동작하지 않습니다. `http://127.0.0.1:3000` (PC), 콘솔에 나온 내부 IP 주소 (휴대폰)로 접속합니다.
- **기존 거래/PNL 기록 유지**: 공용 `%LOCALAPPDATA%\SignalLab` 저장소 및 JSON 구조를 변경하지 않았습니다. 기존 v5.2 이상에서 마이그레이션했다면 다시 가져올 필요 없습니다. 업그레이드 전에는 `backup_data.bat`을 사용한 추가 백업을 권장합니다. 이후 ZIP을 새 폴더에 풀고 서버를 실행하면 됩니다.

`npm test` (자동 테스트), `/api/paper` (모의매매 상태), `/api/scan/diagnostics` (스캔 진단)에서 검사 가능합니다. 실제 Windows·모바일 기기 / 거래소 연결은 실행 환경에서 확인하세요.

참고: 1시간 이상 봉은 잡음이 줄 수 있지만 승률 개선이 검증됐다는 뜻은 아닙니다. 단기 신호 빈도가 줄고 진입 시점이 늦을 수 있습니다.

# Signal Lab v5.2 — 업데이트해도 자동 모의매매·PNL 기록 유지 (PC·모바일 공용)

**이번 버전의 핵심 변경:** 기록을 앱 폴더의 `store.json`에서 분리하고 Windows `%LOCALAPPDATA%\SignalLab\store.json`에 저장합니다. 같은 Windows 사용자 계정으로 실행한 v5.2 이후의 새 버전은 자동으로 같은 데이터를 읽습니다. PC/휴대폰은 PC의 한 서버를 공유하므로 기록도 동일합니다. 별도로 휴대폰에 파일을 복사할 필요가 없습니다. **동시 2개 서버 실행은 기록 충돌 방지를 위해 제한합니다.** 종료된 모의 거래 전체를 누적 보관하며, 화면은 최신 200건을 표시하고 CSV 내보내기는 전체 기록을 포함합니다. (이전 버전에서 이미 삭제된 기록은 복원 불가.)

### 기존 v5.1 기록을 가져오는 방법 — 최초 1회 필수

1. **실행 중인 이전 Signal Lab 서버(start.bat/start_mobile.bat)를 모두 종료**합니다.
2. v5.2 ZIP을 다른 새 폴더에 모두 압축 해제합니다.
3. 새 폴더의 **`migrate_legacy_data.bat`**을 더블클릭하고, 기존 v5.1 폴더(내부에 `store.json`이 있는 폴더)의 경로를 입력합니다. 마우스로 이전 폴더를 창에 끌어다 놓아도 됩니다. (직접 ZIP 경로를 입력하지 말고 압축을 해제한 실제 폴더 선택.)
4. 명령창에 기존 거래 기록 건수와 `가져오기 완료` 표시를 확인한 뒤 **새 `start.bat` 또는 `start_mobile.bat` 실행**. `http://127.0.0.1:3000/api/storage`에서 `persistent:true` 및 거래 건수를 확인합니다.
5. 다음 v5.4, v5.4 ... 업데이트에서는 **처음 1회 가져오기 작업을 다시 할 필요 없이** 새 ZIP을 다른 폴더에 압축 해제해 실행하면 같은 PC 계정의 기록을 이어 사용합니다.

**예외:** 기존 데이터를 수동으로 새 ZIP에 복사했다면 첫 시작에 한해 자동 가져오기도 지원합니다. 그러나 이전 버전 폴더의 `store.json`을 직접 지정하려면 위의 마이그레이션 도구가 확실합니다. 기존 파일을 삭제하지 않습니다.

### 저장·백업·복원

- `open_data_folder.bat`: 공용 기록 폴더 열기. `store.json`은 자동 모의매매의 대기/진행/종료 상태, 매매일지, 관심종목, 알림 식별자 등을 담습니다. `.env`는 텔레그램 토큰, API 키, 설정을 담습니다. **외부에 공유하지 마세요.**
- `backup_data.bat`: 현재 기록을 `%LOCALAPPDATA%\SignalLab\backups\store-날짜.json`에 별도 백업. 실행 시작 때에도 백업을 생성합니다(최신 30개 자동 유지). 중요한 업데이트 전에는 `backup_data.bat`을 권장합니다.
- `restore_data.bat`: 이전 백업 JSON 경로를 입력해 복원. **반드시 서버를 종료한 상태에서만 실행**. 복원 전 현재 기록을 또 백업합니다.
- 이전 버전에서 이미 PNL을 쌓았다면, 반드시 먼저 `migrate_legacy_data.bat`으로 가져오세요. **신호와 실제 시장 가격의 누락 구간은 복원할 수 없으며**, 앱이 꺼져 있던 동안의 거래는 소급 시뮬레이션하지 않습니다.
- 기록 파일이 손상된 경우 **조용히 빈 파일로 초기화하지 않고 실행 오류**로 알려줍니다. `restore_data.bat`으로 정상 백업에서 복원하세요.
- `SIGNAL_LAB_DATA_DIR` 환경변수로 공용 데이터 폴더를 별도로 지정할 수 있지만, 변경하면 다른 데이터셋으로 인식됩니다.
- **PC를 옮기거나 Windows 사용자 계정을 바꾸면** `%LOCALAPPDATA%\SignalLab` 폴더를 안전하게 별도 백업해 복사해야 합니다. 현재 자동 원격/클라우드 동기화는 없습니다.

### 테스트
`npm test` 및 `node --check server.mjs`. 모의매매는 실제 주문을 넣지 않으며, 과거에 발생한 거래의 손익은 시세 관측·가정 스프레드·수수료에 따라 실제 Variational PNL과 다릅니다.

# Signal Lab v4.9 — Mobile LAN Edition (2026-10-19)

### 핵심
- Android Chrome / iPhone Safari에서 읽기 편하도록 **시그널 스캐너를 카드형 UI로 변경**. 진입 구간, 1·2·3차 익절, 검증 상태, TradingView / Variational 바로가기 유지.
- 아래에 모바일 고정 탐색 메뉴(시그널·차트·뉴스·알림) 추가. TradingView 차트·뉴스·버튼의 모바일 폭 최적화. PC 화면은 기존 레이아웃 유지.
- **start_mobile.bat**: PC에서 서버를 사설 Wi-Fi에 공유. 콘솔에 PC의 사설 IPv4 주소와 **모바일 접속 암호** 표시. 같은 공유기 내 모바일 브라우저에서 `http://PC_IP:3000` 접속 후 사용자명 `signal`과 표시된 암호로 인증. PC localhost는 기존대로 로그인 없이 이용.
- 암호를 모르는 다른 LAN 접속은 API·매매일지·서버 알림 스트림 포함 전부 차단. 사설 IP 외의 접속은 로그인 정보를 알아도 거부. 매 실행마다 기본 암호 랜덤 재발급(개인 PC의 `.env`에 `MOBILE_ACCESS_PASSWORD=...`를 직접 지정하면 고정 가능).
- 주의: 이것은 **같은 사설 Wi-Fi 전용**입니다. 4G/5G 외부 접속, 백그라운드 푸시, PC가 꺼진 상태의 스캐닝, 자동 주문을 지원하는 업데이트가 아닙니다. 원격 접속은 VPN 또는 HTTPS 호스팅을 별도로 구성해야 합니다. 암호는 일반 HTTP로 전송되므로 공용 Wi-Fi·포트 포워딩·인터넷 직접 공개 금지.

### PC + 휴대폰 설치법
1. 기존 `start.bat` 종료. 새 ZIP을 PC에 모두 압축 해제. 개인 `.env`와 `store.json`은 필요하면 직접 복사.
2. PC와 휴대폰을 동일한 **신뢰 가능한 개인 Wi-Fi**로 연결.
3. **`start_mobile.bat` 더블클릭**. 콘솔에서 `http://192.168.x.x:3000` 형태의 주소, 사용자명 `signal`, 랜덤 접속 암호 확인.
4. 휴대폰의 Chrome/Safari에서 출력된 주소를 입력하고 로그인. 휴대폰의 `127.0.0.1`은 휴대폰 자신이므로 사용하지 않음.
5. 접속되지 않으면 Windows 방화벽에서 개인 네트워크의 Node.js/포트 3000 허용 여부 및 공유기 단말 분리(게스트 Wi-Fi) 확인. **공용 네트워크에는 절대 허용하지 마세요.**
6. 홈 화면에 바로가기를 추가할 수 있지만 IP 주소가 바뀌면 주소를 수정해야 합니다. 일반 HTTP 로컬 사이트에서는 브라우저 백그라운드 푸시가 제한됩니다. 서버가 실행 중일 때만 텔레그램 알림 가능.

`MOBILE_GUIDE.txt`도 참고하세요. 기존 PC 전용 실행은 `start.bat`로 유지합니다.

# Signal Lab v4.7 — 뉴스 5개씩 페이징·상세 발췌·스캐너 최상단

# Signal Lab v4.6 — 차트 표시 버그 수정 (2026-10-18)

**문제:** Variational/Binance 공통 PERP 메타데이터 검증 실패/지연 시 `app.symbol`을 빈 값으로 설정하고 TradingView 위젯을 그리지 않았음.

**해결:** TradingView 차트는 Binance 선물 심볼만으로 즉시 표시합니다. API 연결을 기다리지 않고 BTCUSDT 기본 차트를 열며, 상단 `차트 보기 ↗`에 원하는 USDT 선물 심볼을 입력할 수 있습니다. 공통 상장 여부가 확인되지 않은 종목의 **거래 바로가기, 분석, 매매 알림은 차단**됩니다. API가 복구되면 자동으로 검증된 종목 분석이 정상 작동합니다. 거래 주문을 자동 실행하지 않습니다.

**설치:** 이전 버전의 검은 실행 창 종료 → ZIP 압축 풀기 → 기존 `.env` 및 `store.json` 필요 시 복사 → `start.bat` 실행 → `http://127.0.0.1:3000` 접속 → `Ctrl+F5`.

TradingView 콘텐츠는 외부 도메인에서 불러오므로 브라우저/방화벽/광고차단 등에 의해 차단될 수 있습니다. 이 경우 차트 아래 **새 탭에서 차트 열기**로 공식 사이트에서 직접 확인합니다. Binance 데이터/Variational 상장 검증 실패는 TradingView 자체 열람을 막지 않습니다.

# Signal Lab v4.5 — 자동 실시간 스캔 안정화 패치 (2026-10-18)

## 실제로 바뀐 점

- 과거 `WebSocket OPEN`만으로 LIVE라 표시하던 동작 수정: **유효한 실제 거래소 시세 / kline 이벤트를 받은 경우에만 실시간 수신 확인**.
- Binance USDⓈ-M 공식 새 `market/ws`, `market/stream` 엔드포인트 유지 (2026-04 구형 종료).
- 1분 간격 정기 재스캔(기본 상위 12 + 순환 18 + 관심 종목). 기존 기본 4분에서 단축. Binance/Variational API 속도 제한과 PC·네트워크 성능에 따라 분석이 지연될 수 있습니다.
- 바이낸스에서 1h/4h/상위·관심 15m 봉 마감 이벤트를 받으면 해당 종목 즉시 분석 예약. 이미 분석이 진행 중이더라도 새 종가 분석이 누락되지 않도록 보완.
- 초기 Binance/Variational 상장 목록 조회 실패 시 **약 20초 간격 자동 재시도** (서버가 실행 중일 때). 오류 기록과 조회 시도 시각 표시.
- 90초 이상 실시간 가격/봉 데이터가 없으면 자동 재연결·재구독. 연결 열림과 실제 데이터 수신을 분리해 오류 탐지.
- `시스템 상태`에 WS 봉 이벤트 실제 수신 시간, 구독 확인/오류, 마지막 실제 시세 수신 시간, 순환 스캔 성공/실패를 별도 표시.
- 표에 `지금 스캔` 버튼 추가. POST `/api/scan` 을 통한 서버 스캔 상태 확인 (실제 가짜 신호 생성하지 않음).
- 기존 TradingView 차트, 확정 패턴, Variational 주문창 바로가기, 호가·비용 필터, RSS 뉴스 및 텔레그램 설정 유지.

**정확한 실시간 범위:** 실시간 Binance WS 시세/봉 마감 수신 + 1분 보완 검사입니다. 모든 종목을 모든 틱마다 전체 재분석하거나 즉시 알림을 반드시 받는 시스템이 아닙니다. Variational 공식 참고 호가는 주기적 REST 조회입니다. 실제 주문은 수동이며 시장 데이터 장애 시 공통 상장 종목의 주문 신호를 차단합니다.

## 처음 실행 및 진단

1. 기존 창의 `start.bat`을 종료합니다. 압축을 풀고 새 폴더의 `start.bat` 실행.
2. 브라우저 `http://127.0.0.1:3000` 열고 `Ctrl+F5`.
3. `시스템 상태`에서 다음을 확인합니다: 바이낸스 WS / 최근 **실시간 가격 수신** / **실시간 봉 데이터 수신** / 정기 스캔 성공·실패.
4. `↻ 지금 스캔`으로 스캔을 요청하고 검사 수가 증가하는지 확인합니다. **조건에 맞는 패턴이 없으면 시그널이 0개여도 정상**입니다.
5. 실패가 지속되면 `http://127.0.0.1:3000/api/status`를 열어 `error`, `marketError`, `scanFailed`, `lastScanFailures`, `liveLastError`를 확인하십시오. API 키/텔레그램 토큰 등은 공유하지 마십시오.
6. `.env`에서 `SCAN_INTERVAL_MS=60000`이 기본. 이전 `.env`에 `SCAN_INTERVAL_MS=240000`이 설정되어 있으면 그 값이 우선합니다. 1분으로 바꾸려면 **기존 .env 값도 수정**하세요.

개발자 확인: `npm test`, `node --check server.mjs`, `node --check public/app.js`. 외부 API와 브라우저 UI 수신은 네트워크 제약 때문에 사용자 Windows PC에서 최종 확인이 필요합니다.

# Signal Lab v4.4 — 버그 점검 및 선택형 안전 업데이트

**핵심 변경:** 대시보드 상단의 기존 캔버스 차트 대신 TradingView 공식 Advanced Real-Time Chart 위젯을 기본 표시합니다.

- **공통 PERP 검증:** 기존 Binance USDT-M × Variational Omni `-PERP` 교집합만 진입 신호로 표시합니다. TradingView에는 같은 Binance 선물 심볼(예: `BINANCE:BTCUSDT.P`)을 전달합니다. 일부 종목은 TradingView의 심볼 제공·구독 조건에 따라 표시되지 않을 수 있습니다.
- **신호에서 차트 선택:** 시그널 표의 `패턴 상세 ↗` 또는 알림 기록의 `내 차트 ↗`를 클릭하면 해당 종목이 TradingView 위젯에 표시됩니다. 관심 종목을 클릭해도 전환됩니다.
- **시간봉 동기화:** 상단 `15분/1시간/4시간/일봉` 버튼은 TradingView 위젯의 기본 간격을 변경합니다. 위젯 내 TradingView 인터벌·지표 도구도 이용할 수 있습니다.
- **넓게/전체화면:** `↔ 넓게`는 차트 영역을 전체 열로 확장하고 `⛶ 전체화면`은 브라우저 전체화면을 사용합니다. Esc로 종료합니다.
- **새 탭:** TradingView ↗ 버튼으로 해당 선물 종목을 공식 TradingView 차트에서 별도 탭으로 엽니다. 차트 제공처가 브라우저에서 차단되면 이용할 수 있습니다.
- **기존 자체 차트 유지:** `자체 차트` 버튼에서 피벗 기반 지지·저항, EMA20/50 오버레이를 확인할 수 있습니다. TradingView 무료 임베드 위젯은 **서버의 자동 분석 지지/저항을 임의로 그리는 API를 제공하지 않으므로**, 분석선은 **오른쪽 ‘선택 종목 분석’ 패널 또는 자체 차트**에서 확인합니다.
- **스캐너는 변경 없음:** 시세 스캔 및 알림 시스템은 기존 Binance/Variational API 기반입니다. TradingView 임베드는 시각화만 담당하며 시그널을 계산하거나 주문을 내지 않습니다. TradingView 화면 시세와 서버의 바이낸스/API 데이터는 갱신 시점이 서로 다를 수 있습니다.
- **외부 연결:** TradingView 위젯 렌더링에는 `https://s3.tradingview.com`과 TradingView 데이터 연결이 필요하며 인터넷 연결/브라우저 보안설정에 따라 차단될 수 있습니다. 네트워크가 차단되거나 외부 서비스를 이용할 수 없으면 자체 차트로 전환합니다. TradingView 무료 위젯에 일부 기능·데이터 제약이 있을 수 있습니다.

5. **매매일지 CSV 백업:** Excel에서 열 수 있는 UTF-8 BOM CSV로 다운로드 가능합니다. 거래 메모 내 스프레드시트 수식 주입 문자를 방어합니다. 기록은 **프로그램 폴더의 `store.json`**에 저장되며 컴퓨터/브라우저를 변경하면 자동으로 동기화되지 않습니다.

# Signal Lab v4.1 — 실시간 이벤트 스캔 · 확정 차트 패턴 · 가상자산 뉴스

Windows 10/11 · Node.js 22+ · Binance USDT-M × Variational Omni 공통 PERP · 자동 주문 기능 없음

## v4.1 핵심 사용법

1. 기존 `start.bat` 실행 창을 종료합니다. 새 ZIP을 **새 폴더에 모두 압축 풀기** 한 뒤, 새 폴더의 `start.bat`을 실행합니다.
2. 브라우저 `http://127.0.0.1:3000` → `Ctrl+F5`를 누릅니다. 안 열리면 검은 명령창의 `[START ERROR]`를 확인합니다.
3. 시그널 표 기본 탭 **확정 차트 패턴 전체**에는 완료된 1시간봉으로 규칙상 확인된 종목을 표시합니다. `진입 검증 통과` 탭은 15분봉, 거래량, 4시간 추세, Variational 참고 호가·펀딩 및 체결비용 필터를 통과한 후보만 표시합니다.
4. **◆ 패턴 확정 · 주문 보류**는 차트 구조가 확인됐지만 조건이 부족해 진입 신호가 아니라는 뜻입니다. **✕ 손절 무효화**는 패턴이 나온 뒤 가격이 손절 기준을 침범해 신규 진입이 부적절하다는 뜻입니다.
5. 각 신호 행의 `패턴 상세`, `Variational ↗` 버튼으로 상세 분석과 수동 주문 화면을 엽니다. **자동 주문은 하지 않습니다.**
6. 뉴스 패널에서 시장 전체 중요 뉴스, 선택 코인 뉴스, 호재·악재 가능성, 키워드 검색을 선택합니다.
7. 상단 `알림 켜기`와 `알림 테스트`로 브라우저 푸시를 확인하세요. PC가 꺼졌을 때는 감시하지 않습니다. Telegram 봇을 연결하면 서버가 실행 중일 때 모바일로 받을 수 있습니다.

## 실시간 스캔과 뉴스의 정확한 범위

- Binance 웹소켓에서 거래 가능한 **양쪽 공통 상장 PERP**의 1시간·4시간봉 마감 이벤트, 유동성 상위/관심 종목의 15분봉 마감 이벤트, 실시간 가격이 기존 지지·저항을 통과하는 이벤트를 받으면 즉시 분석 대기열에 추가합니다. 동시 이벤트가 많으면 대기열 처리 지연이 있을 수 있습니다.
- 백업으로 4분마다 거래량 상위·관심 종목과 나머지 순환 종목을 재검사합니다. 가격 변화를 실시간 구독하더라도 **모든 코인의 모든 틱을 매번 전체 패턴 분석한다는 의미가 아닙니다.** 확정 패턴은 해당 캔들 종가 이후에만 인정됩니다.
- Variational의 상장·참고 호가·펀딩 데이터는 **공식 공개 REST API 주기적 조회**이며 실시간 주문 호가나 확정 체결가격이 아닙니다. 공식 호가가 오래되거나 조건이 불명확하면 주문 신호와 알림은 보류합니다.
- 뉴스는 Decrypt, Cointelegraph, CoinDesk의 RSS에서 **90초마다 새로 조회**합니다. 기사가 게시되어도 RSS 등록·웹페이지 반영 시간이 늦어질 수 있습니다. 실시간 스트리밍 속보를 보장하지 않습니다.
- 호재/악재는 기사 제목 기반 **가능성 분류**입니다. 사실 검증, 가격 영향 또는 투자 방향 예측이 아니므로 원문을 확인해야 합니다. 중요 기사 후보만 중복 방지 후 알립니다. 기사 제공처가 모두 차단되면 상태를 `뉴스 조회 실패`로 표시합니다.
- 매매 알림은 **차트 규칙 확정 + 15분 방향 + 4시간봉 추세 + 최근 시세 + Variational 호가 비용 필터**를 통과한 경우에만 울립니다. **차트 확정만으로 매매 알림을 보내지 않으며**, 보류한 패턴도 표에서 확인할 수 있습니다.

- Variational API 갱신 주기 1분, 공통 상장 교집합 재검증 약 10분, 바이낸스 실시간 시세/4분 순환스캐너는 유지합니다. 
- 고품질 신호의 텔레그램 메시지에 Variational 호가, 신선도, 예상 스프레드와 펀딩 및 거래소 바로가기를 포함합니다.
- **중요한 제약:** Variational 공개 호가는 주문에 제출하는 크기에 대응하는 **확정 체결 호가(firm quote)가 아닙니다**. API 문서상 호가는 최대 600초 전 값일 수 있고, $1,000 표본 호가가 $250/$1,500 주문 체결가를 정확히 나타내지는 않습니다. 서버는 이러한 위험을 줄이기 위해 보수적으로 신호를 차단하지만 안전한 체결을 보장하지 않습니다. 최종 매매는 Variational 주문창에서 참고가격·실제 확정 호가·슬리피지 제한·청산가를 확인한 뒤 수동으로만 진행하세요.
- **실시간 연동의 범위:** Binance WebSocket 시세는 실시간이나 Variational은 **REST 폴링**이며 공식 WebSocket 동시 시세 스트림을 사용하는 것이 아닙니다. 브라우저/PC 종료 뒤에도 서비스를 유지하려면 서버를 별도 상시 운영해야 합니다.

## 동작 방식

- 공통 상장 무기한 선물의 **시세**: 공식 `!miniTicker@arr` WebSocket. 웹소켓 끊김 시 자동 재접속. 시세를 받아도 화면의 `LIVE STREAM` 표시가 아니면 최신 가격으로 단정하지 마세요.
- **차트**: 선택한 종목에 대해 `15m`, `1h`, `4h`, `1d` Kline 조회. EMA20/50, 가격 기반 자동 피벗 지지·저항 표시.
- **진입 후보**: 완료된 1H·4H 봉과 거래량으로 후보를 선별하고, 신규 확정 후보에 한해 15분봉 방향을 추가 검증하여 박스권 돌파, 추세 눌림목, 돌파·리테스트, 유동성 스윕을 규칙 기반 탐지. 목표손익비 최소 2:1 / 24h 거래량 최소 $5M / 4H 추세 및 최소 거래량 확인.
- **스캔 범위**: 매 4분마다 **공통 상장된 종목 중** 거래량 상위 20종목, 순환 배치 30종목, 관심종목을 분석합니다. 나머지는 **순차적으로** 분석하므로 전체 종목의 모든 시간봉을 매초 동시 분석하지 않습니다. 실제 검사 범위와 총 등록 선물종목 수를 웹에 각각 표시합니다.
- **알림**: 새로 검증된 1시간봉·종목·방향·패턴 조합만 1회 알립니다. 웹 브라우저에서는 Notification API, 서버에서는 Telegram Bot (선택 사항). 과거 시그널 자동 재발송 방지 정보는 `store.json`에 보관됩니다.
- **리스크 계산**: 진입~손절 폭과 검증된 Variational 표본 스프레드로 최대 $6의 계획손실 포지션 규모를 보수적으로 산정합니다. 검증에 실패한 경우 기존 차트 계산의 0.12% 가정은 참고값일 뿐 주문 신호로 사용하지 않습니다. 실제 체결가·스프레드·펀딩·슬리피지·청산가는 다를 수 있습니다. 기초자산의 2R·3R 이론목표를 표시하며, 실제 미래 체결 확률은 알 수 없습니다.

### 웹 브라우저를 닫았을 때 알림

`node server.mjs` 프로세스가 **계속 실행 중이라면** 가격 조회와 시그널 스캐너는 계속 작동합니다. 단, 브라우저 알림은 브라우저가 닫혀 있으면 표시되지 않습니다. 브라우저가 꺼진 후에도 Telegram 메시지를 받으려면 다음 설정을 해주세요.

1. Telegram의 공식 **@BotFather**에서 봇을 만들고 토큰을 발급받습니다.
2. 새 봇에서 `/start`를 전송합니다. Bot API `getUpdates`의 `message.chat.id` 필드로 본인 chat ID를 확인할 수 있습니다(봇에 먼저 말을 걸어야 개인 메시지 발송이 가능합니다).
3. `%LOCALAPPDATA%\\SignalLab\\.env` (Windows, 기본 경로)를 만들거나 편집해 `TELEGRAM_BOT_TOKEN=...`, `TELEGRAM_CHAT_ID=...`를 입력하고 서버를 재실행합니다. macOS/Linux는 `~/.signal-lab/.env`가 기본 경로입니다. `SIGNAL_LAB_DATA_DIR`가 설정되었다면 그 디렉터리의 `.env`를 사용합니다. 기존 설치 폴더의 `.env`는 데이터 디렉터리에 파일이 없을 때 첫 실행 시 복사됩니다.
4. 봇 토큰과 chat ID를 공유하거나 GitHub 저장소에 올리지 마세요.

#### 점수 기반 알트코인 관찰용 텔레그램 알림 (선택 사항)

기존 **최종 거래 신호**는 9개 기술 조건 100/100과 별도의 Variational 호가·비용 검증을 모두 통과해야 발송합니다. 다음 기능은 별개의 **관찰 알림**으로, 기술 점수가 지정 값 이상이지만 최종 신호가 아닌 후보를 알리는 용도입니다. 거래 실행 조건을 완화하지 않습니다.

```ini
TELEGRAM_BOT_TOKEN=본인_봇_토큰
TELEGRAM_CHAT_ID=본인_chat_id
TELEGRAM_WATCH_MIN_SCORE=80
TELEGRAM_WATCH_ALT_ONLY=true
TELEGRAM_NEWS_ALERTS=false
```

- `TELEGRAM_WATCH_MIN_SCORE`: 기본 0(OFF), 1~100의 정수로 설정하면 해당 점수 이상인 **확정 1H 패턴**의 관찰 알림을 켭니다. 권장 시작값은 임의의 예시값인 80이며 승률 80%를 뜻하지 않습니다.
- `TELEGRAM_WATCH_ALT_ONLY`: 기본 `true`로 BTCUSDT를 제외합니다(ETH 및 기타 알트코인은 포함). `false`면 BTC도 포함합니다.
- 공통 상장 PERP로 검증된 종목, 75분 이내 확정 패턴에만 발송합니다. 최종 신호와 중복되는 관찰 알림은 보내지 않으며, 종목·방향·패턴·확정봉별 1회만 발송합니다. 재시작 시에도 중복 방지 기록은 `store.json`에 유지됩니다.
- 관찰 알림은 **매매 신호 아님**을 명시하고 기술 미충족 조건과 체결 검증 상태를 보여줍니다. 매수·매도는 실행하지 않습니다.
- `TELEGRAM_NEWS_ALERTS=false`는 뉴스 텔레그램 발송을 끄는 선택 설정입니다. 기존 최종 거래 신호 알림은 유지됩니다.
- 스캐너는 1H/4H 봉 확정 이벤트와 정기 스캔으로 동작하며 모든 코인을 틱 단위로 즉시 재평가하지는 않습니다. PC/VPS와 서버가 종료되면 알림도 중단됩니다.

**24시간 서비스**는 항상 켜져 있는 PC 또는 VPS에서 이 서버를 지속 실행해야 합니다. 로컬 PC가 꺼지면 스캔과 알림도 중단됩니다. 휴대폰에서 사이트에 접속하려면 서버가 실행된 PC와 동일 LAN에서 `HOST=0.0.0.0`으로 서버를 실행하고 `http://PC_IP:3000`에 접속할 수 있습니다. 로컬 공유기 밖의 공용 인터넷에 직접 노출하지 말고 HTTPS/인증/방화벽을 별도로 구성하세요. 모바일 브라우저는 HTTP 환경에서 알림을 허용하지 않을 수 있습니다.

## 기술/검증 주의

- 서버는 바이낸스 공식 REST `https://fapi.binance.com/fapi/v1/` 과 WS `wss://fstream.binance.com`에 연결합니다. 지역 제한, 사내망, 서비스 장애, IP 차단 등으로 접속되지 않을 수 있습니다. 로컬 가짜 응답을 이용한 서버 통합테스트로 필터 동작을 확인했지만, 사용자 PC에서 외부 바이낸스·Variational 서버에 실시간 접속되는지는 별도로 확인해야 합니다.
- Binance USDT 무기한 선물과 Variational Omni PERP **양쪽에 동일 기본자산이 상장된 경우만** 포함합니다. 현물·SWAP·USDC/BTC 결제 선물·단위 불일치 계약은 제외합니다.
- 지지·저항은 가격 피벗을 바탕으로 **추정**하며 거래소 실측 주문장 매물벽이나 볼륨 프로파일(POC)이 아닙니다.
- 1시간봉 마감 기준이므로 1시간 내 초단타 시그널은 놓칠 수 있습니다. 높은 레버리지에서 알림 도착 당시 진입가/청산가를 반드시 새로 확인하세요.
- 점수는 **조건 만족도 점수**이지 통계적으로 보정된 승률이나 수익 확률이 아닙니다. 손절 주문 갭·펀딩비·실거래 미끄러짐 등은 반영하지 않습니다.
- 추천값은 모의 전략의 기술적 후보이며 재무적 보장/주문 지시가 아닙니다.

## 가격 비교 시 해석 방법

- **Binance last**: 최근 체결가. 호가창의 즉시 체결 가능한 매수/매도 가격이 아닙니다.
- **Variational Mark**: 미실현손익·마진 및 청산에 쓰이는 기준 가격. OLP의 실제 주문 호가가 아닙니다.
- **Variational Bid/Ask**: 공개 API에 게시된 *참고* 호가. 현재와 동시화된 firm quote를 보장하지 않습니다.
- **스프레드 비용 추정**: 현 매수가와 매도가의 차이를 왕복하여 지불한다고 가정한 상한이 아닌 추정치. 실제 청산 시 새 호가에 따라 달라지고 가격 방향 손익, 지연·실제 슬리피지, 펀딩·청산 페널티는 별도입니다.
- **펀딩 1회 추정액**: 공개된 현재 구간 금리 × 명목금액을 방향에 따라 부호 처리한 값. 플러스는 고객이 지불(화면 `-`), 음수는 수취(화면 `+`)로 표시. 다음 지급 때 금리는 달라질 수 있으므로 예상치로만 사용합니다.
- **전략 적합성 필터**: 임의 기준 비용·데이터신선도 필터입니다. 백테스트된 승률이나 지표가 아니며 수익성을 증명하지 않습니다.
- Variational은 지역 및 계정별 이용 제한이 있을 수 있습니다. 링크가 존재해도 매매가 허용된다는 뜻이 아닙니다.

- 릴리스 JSON 형식은 `{"version":"4.5.0","files":[{"path":"public/app.js","url":"./v4.5.0/public/app.js","sha256":"<64자 SHA256>"}]}`처럼 각 파일의 다운로드 경로와 해시를 포함합니다. URL은 **같은 HTTPS 출처**로 제한합니다. 릴리스 서버 운영은 이 프로젝트가 대신 제공하지 않습니다.
- 새 파일 업데이트에는 JSON manifest의 `version`과 `files`가 필수이고, `start.bat`에서 `update-cli.mjs --apply`가 무결성을 재확인한 후 실행합니다.
- 업데이트 검증은 다운로드 파일 변조 감지용으로, **배포 계정 해킹이나 악성 운영자를 막는 서명 체계는 아닙니다.** 출처를 신뢰할 수 있을 때만 URL을 입력하세요.

**수동 교체 시** 새 ZIP을 별도 폴더에 압축을 풀고, 이전 `.env`·`store.json`을 새 폴더로 복사하는 방식을 유지할 수 있습니다.

- 실시간 가격 스트림이 120초 넘게 멈추면 자동 재연결하는 감시 루틴을 추가했습니다.

## v5.0: TradFi SWAP (PC + 모바일 통합)

- Variational **Mark Price / 참고 Bid·Ask / 현재 호가 갱신시각 / 스프레드 / 24H 거래량 / LONG과 SHORT의 서로 다른 SWAP 펀딩비 / $1,000 명목 금액에 따른 예상 펀딩 수취·지급** 정보를 보여줍니다.

- 확인된 공식 Variational SWAP 거래 주소만 `Variational 주문창`으로 제공합니다. 매핑 불확실한 종목은 `Variational 시장 확인` 링크로 표시합니다. 실제 주문은 사용자가 직접 넣습니다.
- 외부 캔들 API가 필요한 이유: TradingView 공개 임베드 위젯에서는 OHLC 캔들 데이터를 자동화 분석용으로 추출할 수 없고, Variational 공개 stats API는 과거 15분·1시간·4시간봉 전체를 제공하지 않습니다.
- **선택적 TradFi 기술 패턴 스캔:** [Twelve Data](https://twelvedata.com/) 계정에서 받은 API 키를 `.env`의 `TWELVE_DATA_API_KEY`에 기입하면, 기본 XAU/XAG(사용자 설정 변경 가능) 대상으로 15분·1시간·4시간 참조 OHLC 데이터를 15분 주기로 조회합니다. 외부 캔들 유효성, 데이터 신선도, 4H EMA20/50+기울기, 1H 20봉 돌파·봉 강도, 15분봉 방향, Variational 호가·기초자산 가격 차이(100bp 이내), 손절 거리 등을 통과한 종목에 한해서만 *확정 기술 패턴(체결 미확정)*을 표시합니다. 2R, 3R, 4R의 40/35/25% 분할 익절 참고가격은 자동 계산됩니다.
- 실제 XAU/XAG의 외부 시세 심볼이나 Twelve Data 요금제/데이터 제공 범위는 사용자의 계정에서 검증해야 합니다. 호출량 한도·사용요금·저작권·지원 시장·지연 정보는 공급자 약관을 확인하세요. 15분 주기 REST는 **진정한 틱 단위 실시간**이 아닙니다. 외부 전송 권한이나 공급자의 실시간 데이터가 필요할 수 있습니다.
- 공급자 API 실패·호가가 오래됨·시장 휴장 가능성·심볼/가격 괴리·데이터 누락 시 **신규 TradFi 확정 신호를 내지 않습니다.** 직접 TradFi 주문은 자동으로 실행하지 않습니다.
- 바이낸스×Variational 크립토 PERP의 기존 실시간 이벤트 스캔은 기존대로 유지됩니다. TradFi SWAP은 다른 계약 유형이라 크립토의 공통 Binance 상장 조건을 적용하지 않습니다.
