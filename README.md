# Signal Lab — Issue #6 통합 개발판

Binance USDT 무기한 선물의 확정 1H·4H **차트**로 분석하고, 실제 매매 대상 거래소인 **BingX·Gate.io**의 공개 시세를 함께 보는 로컬 PC·모바일 대시보드입니다. Binance는 차트 분석 기준으로만 사용합니다. 최신 구현·검증 이력은 [ISSUE6_INTEGRATION_KO.md](ISSUE6_INTEGRATION_KO.md)를 참고하세요. 거래 점수는 승률이 아니며 **새 전략의 실전 성능은 미검증**입니다.

이 버전은 이전 공급자의 네트워크·API·UI·링크 의존성을 제거합니다. 대체 시세 공급자가 없는 **TradFi 수집·스캔·신규 모의 진입은 비활성**입니다. 기존 TradFi 포지션·PNL·매매일지는 보존하지만 시세를 갱신하지 못하므로 마지막 관측값을 현재 가격으로 해석하면 안 됩니다.

화면 버전 이름은 한국 시간 기준으로 `YYYY-MM-DD_ver1` 형식을 씁니다. 같은 날의 다음 버전은 `ver2`부터 증가합니다. 화면 이름은 `package.json`의 `displayVersion`에, 업데이트 비교용 버전은 `version`에 기록합니다.

## Windows 설치와 기록 보존

1. 이전 서버 창을 종료하고 필요하면 기존 `backup_data.bat`으로 백업합니다.
2. 새 ZIP을 별도 폴더에 모두 풉니다. 압축파일 내부에서 실행하지 마세요.
3. [Node.js](https://nodejs.org/) 22 또는 24를 설치하고 `start.bat`을 실행합니다. 기본 주소는 `http://127.0.0.1:3000`입니다.
4. 기존 `%LOCALAPPDATA%\SignalLab\.env`와 `store.json`을 덮어쓰거나 초기화하지 마세요. 서버는 기존 중앙 저장 경로를 계속 사용합니다. 예제 환경 파일을 기존 `.env` 위에 복사하지 마세요.

macOS/Linux에서는 `node server.mjs`로 실행합니다. 기본 데이터 경로는 `~/.signal-lab`이며 개발·테스트는 별도 `SIGNAL_LAB_DATA_DIR`을 사용해야 합니다. 설치에 외부 npm 패키지는 필요하지 않습니다.

모바일은 동일한 신뢰할 수 있는 사설 Wi-Fi에서 `start_mobile.bat`을 실행한 뒤 명령창의 PC 주소·임시 암호로 접속합니다. PC 서버가 계속 켜져 있어야 합니다. 공용 인터넷에 포트를 개방하지 마세요. 자세한 내용은 [MOBILE_GUIDE.txt](MOBILE_GUIDE.txt)를 참고하세요.

기존 관심종목, Telegram `.env`와 발송 이력, PNL, 미청산 포지션, 매매일지, Windows 알림, 백업·복원 경로를 유지합니다. 과거 포지션의 TP/SL은 신규 규칙으로 다시 계산하지 않습니다. 데이터 복원은 서버를 종료한 뒤 `node data-cli.mjs restore "백업 JSON 경로"`로 수행하며, 현재 파일은 먼저 보존됩니다. 실험 Journal은 운영 저장에 연결하지 않습니다.

## 분석·최종 신호

- 스캔 대상은 Binance의 `TRADING`·`USDT`·`PERPETUAL` 계약입니다. 완전히 마감된 4H 250개 이상이 필요하며 서버는 미확정봉을 제외할 수 있도록 301개를 요청합니다.
- 단일 100점: 4H EMA200 15, EMA100 5, 1H EMA20 10, 패턴·확정봉 강도 25, ADX/DMI 15, RSI 10, MACD 5, 패턴 거래량 10, ATR 5점입니다. 평가 불가능하면 점수는 `null / 평가 불가`입니다.
- **`SIGNAL_FINAL_MIN_SCORE=90`은 제안 기본 임계값이며 검증 상태는 `UNVERIFIED`입니다.** 실측 수익률·기간 외·워킹 포워드 결과로 최적화된 값이 아닙니다. 점수 통과와 기술·신선도·손절·호가·위험·매물대 검증 및 실거래 승인은 별개입니다. 설정은 90~100의 정수만 허용하며 잘못된 값이면 서버 시작을 차단합니다. 기존보다 낮은 기준으로 완화하거나 설정 변경으로 실제 주문을 승인하지 않습니다.
- 기본 60초 보완 스캔은 관심종목·거래대금 상위 12개·순환 18개와 확정봉 이벤트를 처리합니다. 전체 종목을 매초 재분석하는 시스템이 아닙니다. 화면의 실제 처리 건수와 연결 상태를 확인하세요.
- 메인에는 검증 완료된 최종 신호만 점수 내림차순 → 최신 확정봉 → 종목명 순으로 표시합니다. **Telegram은 현재 화면의 최종 판단 목록(`/api/results.signals`)에 남아 있는 검증 신호만 전송합니다.** 본문은 종목·방향·배율·포지션 수량(모의) 네 줄입니다. 같은 신호의 실제 모의 진입 원장에서 확인된 값만 사용하며, 엔진의 기본 추천 배율이나 계획 수량으로 채우지 않습니다. 진입 전에는 '미설정·미확인'이 정상입니다. 발송 직전에 최신 호가·기술·진입·매물대 조건을 다시 확인하며, 동일 조건으로 매칭되지 않으면 전송하지 않습니다. 기존 관찰 알림과 뉴스 Telegram 발송은 중지되며, 브라우저 뉴스와 기존 Telegram 설정/발송 이력은 보존합니다.

## 매물대 TP·모의매매

실제 Binance aggTrades 체결량을 가격별로 집계해 POC·HVN·Value Area와 기간·커버리지·갱신 시각을 기록합니다. 1H 캔들 거래량을 실제 가격별 매물대로 대체하지 않습니다. 기술 후보·보유 포지션 중심의 제한된 공개 조회만 수행합니다.

신규 거래에는 LONG 진입가 위 또는 SHORT 아래의 서로 다른 매물대 세 개가 필요합니다. 틱·스프레드·비용·최소 수량·순손익비를 검증하고 40% / 35% / 25%로 분할합니다. 데이터 부족·지연·목표 순서·수량 오류는 `TP_PROFILE_UNAVAILABLE`로 보류하며 고정 2R·3R·4R을 자동 생성하지 않습니다.

TP1의 실제 **모의 체결 누적 수량 40%**가 완료된 뒤에만 잔량 손절을 한 번 본절로 이동합니다. `TP1_MOVE_STOP_TO_BREAKEVEN=true`와 `TP1_BREAKEVEN_MODE=ENTRY_FILL`이 제안 기본값입니다. `COST_COVERED` 모형도 선택할 수 있지만 비용 보전은 가정이며 갭 손실·무손실을 보장하지 않습니다. PC·모바일 설정 변경은 신규 포지션부터 적용합니다.

PNL은 모의 체결·명시된 비용 가정이며 실제 거래소 체결·실제 계정 수수료·현재 펀딩 정산과 다릅니다. 기존 원장의 펀딩 미반영 여부는 화면에 표시합니다. 시세 단절·PC 종료 중에는 포지션 평가에 공백이 생깁니다. 실제 수익률로 해석하지 마세요.

## BingX·Gate.io 시세 조회 (1단계)

`BingX·Gate.io 시세` 메뉴(`#venues`)에서 관심 종목(최대 6개)의 두 거래소 USDT 무기한 선물 **최우선 매수/매도 호가·스프레드·두 거래소 간 가격 차이·Binance 차트가 대비 차이**와 계약 규칙(가격 단위, 수량 단위, 최소 수량, 최소 주문금액, 거래 가능 여부)을 봅니다.

- 공개 시세 GET만 사용합니다. **API 키·계좌·주문 기능은 없습니다.** `GET /api/venues?symbols=BTCUSDT,ETHUSDT`
- BingX: `open-api.bingx.com` (`/openApi/swap/v2/quote/contracts`, `/quote/depth`). 공식 제한이 IP당 초당 1회라 요청 간격을 1.1초로 지키고, 화면이 열려 있을 때만 20초마다 갱신합니다. 네트워크 실패 시에만 `open-api.bingx.pro`로 재시도합니다.
- Gate.io: `api.gateio.ws/api/v4` (`/futures/usdt/contracts`, `/futures/usdt/order_book`). 주문 수량은 **계약 수** 단위이며 1계약 = `quanto_multiplier` 기초자산입니다.
- 거래 가능 판정: BingX `status=1`·`apiStateOpen`·`apiStateClose`=true, Gate.io `status=trading`·`in_delisting=false`. 15초보다 오래된 호가나 역전된 호가는 오류로 표시합니다.
- 실제 PC에서 연결 확인: `npm run test:venues` (또는 `npm run test:venues -- SOLUSDT,XRPUSDT`).

## 모의매매 체결 기준: BingX·Gate.io (2단계)

- 신호는 **Binance 차트**(확정 1H·4H, 체결량 매물대)로 분석하고, 모의 수량·진입·청산은 **실제 매매 거래소 호가와 계약 규칙**으로 계산합니다.
- 기술 검증을 통과한 신호마다 두 거래소의 최신 호가로 수량·위험을 계산하고, **진입가가 더 유리한 거래소**(롱은 낮은 매도호가, 숏은 높은 매수호가)를 고릅니다. 같으면 `PAPER_VENUES`의 앞 거래소입니다. 거래 불가·미상장·15초 넘은 호가 거래소는 제외합니다.
- 손절은 그 거래소 가격 단위로 진입가에서 먼 쪽으로 맞추고, 목표가도 그 거래소 가격 단위로 맞춥니다. Gate.io 수량은 계약 수(정수)로 맞춥니다.
- 진입 대기·보유 중인 모의 포지션은 **선택된 거래소 호가로만** 4초마다(`PAPER_VENUE_REFRESH_MS`) 추적합니다. Binance 가격은 이 포지션을 움직이지 않습니다.
- 수수료 가정은 거래소 공개 Taker 요율과 기본 가정(0.06%) 중 큰 값입니다. 실제 계정 요율·펀딩 정산은 아닙니다.
- 전환 전에 열린 기존 모의 포지션은 기록이 끊기지 않도록 기존처럼 Binance 시세로 추적합니다. 화면·CSV에 거래소가 표시됩니다.

## 실매매 화면 (자동 모의매매 대체, 2026-11-12)

API 실주문이 확인되어 **자동 모의매매는 기본으로 꺼졌습니다.** 예전 `자동 모의매매 PNL` 자리에 **실매매** 화면이 있습니다.

- 위쪽 큰 표시: `TESTNET (모의 자금)` / `LIVE (실제 돈)` / `OFF`, 활성화 여부, 긴급 정지, 거래소, 잔고(30초마다 조회).
- 버튼: 활성화 · 비활성화 · 긴급 정지 · 긴급 정지 해제 · (테스트넷만) 시험 주문.
- 보유 포지션 카드: 종목·방향·배율, 첫 진입가, 추매 n차/최대, 평균 진입가, 현재가, 수량, 미실현 손익(USDT·증거금 대비 %), 손절가, TP1~3, 대기 중인 추매 주문, 상태. 가격은 모두 거래소 가격 단위의 같은 자릿수로 표시합니다. 카드에서 **손절·TP 직접 수정**도 할 수 있습니다(새 손절을 먼저 넣고 옛 손절 취소).
- 종료된 거래: 거래소 정산 기록(BingX 자금 흐름: 실현 손익·수수료·펀딩)으로 수수료 반영 손익을 보여 주고, 거래 수·승률·누적 손익을 합계합니다. 정산 기록을 읽지 못하면 관측한 시세로 계산한 값을 **추정**으로 표시하며, 근거가 없으면 숫자를 만들지 않습니다. 테스트넷 시험 주문은 합계에서 뺍니다.
- 최근 진입 제외 사유는 한국어로 표시합니다.
- 자동 모의매매를 다시 켜려면 `.env`에 `PAPER_TRADING=on`. 끈 동안에는 새 모의 진입·1/5/15분 단타(모의 전용)·모의 알림(텔레그램·Windows·화면)이 없고, 예전 모의 기록은 `store.json`에 그대로 남습니다(`/api/paper/export` CSV).

## 실주문 (3단계) — 기본 OFF, 테스트넷부터

최종 신호가 처음 발행될 때 모의매매와 같은 거래소·방향·손절·목표가로 **실제(또는 테스트넷) 주문**을 보낼 수 있습니다. 아래 조건이 모두 맞아야만 주문이 나갑니다.

1. PC의 데이터 폴더 `.env`(Windows: `%LOCALAPPDATA%\SignalLab\.env`)에 직접 입력합니다. **키를 채팅·화면·Git에 넣지 마세요.**
   ```text
   LIVE_TRADING_MODE=TESTNET          # OFF(기본) · TESTNET · LIVE
   BINGX_API_KEY=...                  # 출금 권한 없는 선물 거래 전용 키 권장
   BINGX_API_SECRET=...
   GATEIO_API_KEY=...
   GATEIO_API_SECRET=...
   # LIVE일 때만 추가로 필요
   # LIVE_TRADING_CONFIRM=REAL_MONEY
   ```
2. 서버를 켤 때마다 `알림` 화면의 **실주문 제어 → 활성화**를 눌러야 합니다(재시작하면 자동으로 비활성).
3. BingX 계정은 **단방향(one-way)·양방향(hedge) 포지션 모드 모두** 됩니다(2026-11-17): 진입 직전에 계정 모드를 읽어 포지션에 기록하고, 그 포지션의 손절·목표·청산·본전 이동은 진입 때 모드로 보냅니다(헤지 모드는 positionSide LONG/SHORT, reduceOnly 없음). 모드를 읽지 못하면 진입하지 않습니다. Gate.io는 단일(single) 포지션 모드여야 하며 양방향 모드면 주문하지 않습니다. 마진 모드와 배율은 **진입 직전에 자동 설정**합니다: 해당 종목을 교차(Cross) 마진으로 바꾸고, 점수·시총 배율(10~30배, 거래소 최대치를 넘으면 최대치로)로 맞춘 뒤 다시 읽어 확인합니다. 설정이나 확인이 실패하면 그 진입은 보내지 않습니다(그 종목에 이미 포지션·주문이 있으면 거래소가 마진 변경을 거부합니다). API 키에 선물 거래 권한이 필요합니다.

주문 방식과 안전장치:
- **BingX:** 시장가 진입에 손절(STOP_MARKET, 마크 가격)을 붙여 보내므로 포지션이 생기는 순간부터 손절이 걸려 있습니다. 이어서 1·2·3차 목표가에 40/35/25% 감축 전용 익절을 겁니다.
- **Gate.io:** 시장가(IOC) 체결을 확인한 뒤 즉시 마크 가격 손절(전량 청산 트리거)과 감축 전용 익절 3개를 겁니다. **손절 등록이 실패하면 즉시 시장가로 청산하고 긴급 정지**합니다.
- 1차 익절(40%) 체결이 확인되면 **새 본절 손절을 먼저 건 뒤** 기존 손절을 취소합니다. 포지션이 0이 되면 남은 주문을 취소합니다(15초마다 거래소와 대조).
- 같은 신호는 고정 주문 ID로 한 번만 보냅니다. 주문 결과가 불확실(시간 초과)하면 다시 보내지 않고 주문 ID로 조회하며, 확인되지 않으면 **긴급 정지 후 사람 확인을 요구**합니다.
- **수량 (`LIVE_SIZING=BALANCE`, 기본)**: 진입 직전에 거래소의 **남은(사용 가능) 증거금**(BingX availableMargin·Gate.io available)을 조회해 모의매매와 같은 규칙으로 정합니다. 첫 진입 1단위 = 남은 증거금 × `DCA_UNIT_PCT`(0.19%) × 배율, 매물대마다 1·1·2·4·8 … 단위 지정가 추매(포지션 1 → 2 → 4 → 8배로 커짐, 최대 `HOURLY_MAX_ADDS`회, 기본 7), 손절은 마지막 추매 바깥에 포지션 전체 기준 하나. 새 포지션 하나(첫 진입 + 걸어 둘 추매 전부)의 증거금은 남은 증거금의 `LIVE_MARGIN_USE_PCT`(기본 25%) 이내로 줄여 맞추고, 그래도 안 되면 `MARGIN_SHORT`로 건너뜁니다. 앞 포지션이 쓴 만큼 남은 증거금이 줄어 다음 포지션은 자연히 작아집니다(25% → 남은 75%의 25% …). 하루·열린 손실 한도는 순자산 기준. 추매가 체결되면 익절 3개를 커진 포지션의 40/35/25%로 다시 걸고, 1차 익절이 체결되거나 포지션이 0이 되면 남은 추매 주문을 취소합니다. 맞는 매물대가 없으면 1단위 + 패턴 손절.
- 첫 진입 증거금 = 주문 시점 BingX 잔고(평가 손익 포함) × `DCA_UNIT_PCT`(기본 0.19%). `LIVE_MIN_UNIT_MARGIN_USD`에 금액을 넣으면 그 금액을 하한으로 씁니다(기본 0 = 하한 없음). 최대 손실 한도는 그대로 적용됩니다.
- 한도: 1회 최대 손실(모든 추매 체결 후 손절) 잔고의 `DCA_MAX_LOSS_PCT`(기본 30%), 하루 계획 손실 합계 잔고의 `LIVE_DAILY_MAX_LOSS_PCT`(기본 60%), 동시 포지션 개수는 기본 제한 없음(`LIVE_MAX_OPEN_POSITIONS`에 숫자를 넣으면 짝수·롱숏 반반으로 제한), 대신 열린 포지션들의 최대 손실 합계가 잔고 × 하루 손실 한도 이내(`OPEN_RISK_LIMIT`), 거래소 `LIVE_VENUES`(기본 둘 다). `LIVE_BALANCE_CAP_USD`(기본 0 = 잔고 전체)를 넣으면 잔고가 그보다 많아도 그 금액까지만 기준으로 씁니다(예: 테스트넷 가상 100,000 USDT를 실제 $400처럼, `LIVE_BALANCE_CAP_USD=400`). `LIVE_SIZING=RISK_USD`로 바꾸면 예전 고정 금액 방식(`LIVE_MAX_RISK_USD` $2, `LIVE_DAILY_MAX_RISK_USD` $6)을 씁니다.
- **긴급 정지**는 신규 진입만 막고 손절 주문은 그대로 둡니다(재시작해도 유지). 보유 포지션 청산은 거래소에서 직접 하세요.
- 실제 손익·체결가·수수료의 기준은 거래소 계정입니다. 이 화면의 기록은 주문 상태 기록입니다.

## 테스트넷 단타 와이코프 기록

5분봉 단타 후보와 진입 결과를 기록하는 `scalp/signals-YYYY-MM-DD.jsonl`에 `wyckoff` 항목을 추가합니다. 해당 5분봉 마감 시각까지 확정된 빙엑스 15분봉으로 박스, 국면, 마지막 이벤트 및 확인 시각을 계산합니다. 로그의 `alignment`는 확정 박스와 후보 방향의 일치 여부입니다. 판정 정보가 부족할 때는 상태만 남깁니다.

공유된 Wyckoff Structure Map 설정과 공개 설명을 바탕으로 계산한 관측값입니다. ATR은 Wilder 14봉을 사용하고 Standard ST는 종가가 박스 안에 있고 저점 또는 고점이 정지 구간의 1 ATR 이내인 저거래량·좁은 스프레드 재시험으로 추정합니다. 단타 진입 조건이나 추매·청산 규칙에는 사용하지 않습니다.

같은 15분봉에서 VSA 6.2의 원본 기준인 현재 봉 포함 50봉 거래량 z-score와 절정(2.5)·확장(1.0) 여부를 `vsa`에 기록합니다. Map이 찾은 절정 봉과 AR 범위에서 엄격 ST 또는 완화 ST를 비교합니다. 저거래량은 50봉 평균 미만, 완화 ST 피벗은 좌우 3봉으로 해석했습니다. ST가 확인된 범위는 AR 이후 최소 15봉부터 각 종가가 같은 경계 밖으로 1 ATR 이상 나온 3연속 이탈을 기록합니다. 빠른 복귀에 따른 재분류 등 보호된 Pine 코드의 추가 동작은 포함하지 않습니다.

### 백테스트 (과거 데이터 검증)

`backtest.bat`을 더블클릭하면 최근 60일 Binance 공개 캔들(1시간·4시간·15분·5분봉, 6개 종목)을 받아 서버와 같은 판단 함수로 다시 돌리고 `backtest-results\report.txt`에 결과를 씁니다. 키는 필요 없습니다. 처음엔 캔들을 받느라 몇 분 걸리고, 다음부터는 `backtest-cache`에 저장된 캔들을 재사용합니다.

- **1시간봉 분할 추매 비교**: 결과의 `[1-1]`에서 기존(패턴 손절, $6 위험)과 분할 추매(잔고 `--balance`, 기본 1000)를 나란히 봅니다. 인터넷 없이 이미 받은 캔들만 쓰려면 `--offline`.
- 2026-05-14~11-10 180일·12종목·잔고 $400 결과: 기존 268건 +$292(PF 1.25), 분할 126건 +$974(PF 3.06, 승률 71%). 단, 분할 수익의 63%가 거래 1건(+$618, 추매 7회 후 34일 보유, 손절 7% 앞에서 반등)에서 나왔고, 전반 90일은 −$66, 최악 거래 −$98(잔고의 −24.6%), 평균 보유 7일입니다. 표본이 작아 우연일 수 있습니다.

- 보고서 항목: ① 1시간봉 현재 기준(90점+) 패턴별 성과 ② 점수 구간별(90+/85~89/80~84/80 미만) 성과 — 90점 기준이 맞는지 판단용 ③ 5분봉 단타(고정 위험) ④ 단타 + 매물대 분할(잔고 대비 손익·최악 거래·보유 중 최대 평가손)
- 체결 가정(보수적): 신호 봉 마감 직후 5분봉 시가 진입, 같은 5분봉에서 손절·익절이 모두 닿으면 손절 우선, 갭은 시가 체결, 매 체결 수수료 0.06% + 슬리피지 0.02%. 펀딩비·실제 호가 깊이는 반영하지 않습니다.
- `trades.csv`에 모든 거래가, `summary.json`에 신호 흐름과 설정이 남습니다.

### 단타 되돌림 1분·5분·15분봉 (모의 전용)

`SCALP_INTERVALS`(기본 `1m,5m,15m`)의 시간봉을 모두 봅니다. 규칙은 봉 개수로 같고, 시간봉별로 아래만 다릅니다.

| 시간봉 | 최소 움직임 | 진입 대기 | 시간 청산 |
|---|---|---|---|
| 1분 | 1.2% (6분 안) | 2분 | 24분 |
| 5분 | 2.5% (30분 안, `SCALP_MIN_MOVE_PCT`) | 5분 | 2시간 |
| 15분 | 4.3% (90분 안) | 15분 | 6시간 |

1분·15분 최소 움직임은 5분 기준을 시간의 제곱근으로 환산한 값입니다. 15분봉 180일 백테스트: 최소 2.5% −$60, 3.5% −$4, 4.3% +$2.8(26건), 5.5% −$19로 4.3%가 가장 나았지만 수익이라 보긴 어렵습니다. 1분봉은 `backtest.bat`이 최근 30일(`--scalp-1m-days`)을 받아 [3-1] 항목에 비교합니다.

### 동시 포지션 · 절반 크기

모의 포지션은 동시에 `PAPER_MAX_POSITIONS`(짝수 2~10, 기본 6, 홀수를 넣으면 올림)개까지 잡고, **롱·숏을 반씩** 나눕니다(기본: 롱 3 + 숏 3). 한쪽이 다 차면 그 방향 신호는 `롱/숏 포지션 상한`으로 건너뛰고 반대 방향은 계속 받습니다. 다른 포지션이 열려(또는 진입 대기) 있으면 새 포지션은 가장 최근에 연 포지션의 절반 크기로 들어갑니다(예: $1 → $0.5 → $0.25). 모두 청산되면 다시 원래 크기입니다. 절반 크기가 거래소 최소 주문보다 작으면 진입하지 않습니다(`HALF_SIZE_BELOW_MINIMUM_ORDER`). 실주문 수량에는 적용하지 않습니다.

#### 5분봉 단타 세부 규칙

`SCALP_MODE=ON`(기본). 실주문으로는 보내지 않습니다.

- **급락 후 반등 롱 / 급등 후 되돌림 숏**: 최근 30분(5분봉 6개) 안에 2.5% 이상(`SCALP_MIN_MOVE_PCT`) + ATR 4배 이상 움직이고, 거래량이 평소 중앙값의 3배 이상 터지고, RSI(14)가 25 이하/75 이상을 찍은 뒤, 마감된 5분봉이 반대 꼬리(꼬리 50% 이상) 또는 직전 봉 돌파로 마감하면 진입합니다. 이미 30% 이상 되돌린 뒤에는 진입하지 않습니다.
- **손절**: 극단값(저점/고점) 바깥 0.25 ATR. **TP**: 움직임의 50% / 61.8% / 78.6% 되돌림, 40/35/25% 분할. 비용 반영 TP1 손익비 1R 미만이면 진입 안 함.
- **진입 대기 5분**, **최대 보유 2시간**(넘으면 시간 청산).
- 1분마다 실시간 시세로 크게 움직인 종목을 최대 6개만 골라 5분봉을 조회합니다. 상태: `/api/scalp`.

### 매물대 분할 진입 (모의 전용: 단타 + 1시간봉)

`DCA_MODE=ON`(기본). 단타 되돌림 신호와 1시간봉 신호 모두에 적용하며 실주문으로는 보내지 않습니다.

- **1시간봉**(`STOP_ZONE_ADDS`, 기본 켜짐): 한 번의 매매로 봅니다. 첫 진입 1단위 → 매물대마다 추매(5~10분할) → 마지막 추매 매물대 바깥에 손절. 배율은 점수·시총 배율(10~30배)을 씁니다. 맞는 매물대가 없으면 기존처럼 패턴 손절 한 번으로 진입합니다. `STOP_ZONE_ADDS=false`로 끕니다.
- **매물대를 못 찾을 때**: 15분봉(3일+14일) 매물대로 맞는 추매 자리가 없으면 1시간봉 30일 → 4시간봉 90일 매물대로 바꿔 가며 찾습니다. 셋 다 없을 때만 패턴 손절로 진입합니다.
- **교차(Cross) 마진**: 모의 계좌 전체(`PAPER_BALANCE_USD` + 누적 실현 손익)가 모든 포지션을 받칩니다. 추매 안전 검사와 화면의 예상 청산가 모두 교차 마진 기준입니다(다른 포지션의 평가 손익 포함, 유지증거금 0.5% 가정).

- **수량**: 첫 진입 1단위 = 잔고(`PAPER_BALANCE_USD`, 기본 400 + 누적 모의 손익)의 `DCA_UNIT_PCT`(기본 0.19%) 증거금 × 배율(`DCA_LEVERAGE`, 10~30, 기본 10). 추가는 1, 2, 4, 8 … 단위. 물타기 횟수 최대 `DCA_MAX_ADDS`(5~10, 기본 10회, 단타). 1시간봉은 `HOURLY_MAX_ADDS`(5~10, 기본 7회): 180일 백테스트에서 10회보다 수익 +$1079→+$1150, 전반기 −$59→+$12, 최대 낙폭 −$181→−$134, 최악 거래 잔고 −24.6%→−12.7%.
- **추가 위치**: 15분봉 3일 매물대(HVN)와 15분봉 `DCA_ZONE_DAYS`일(3~15, 기본 14일) 매물대를 합친 것 중(1분 단타는 최대 24분 보유라 3일 매물대만 사용) 포지션 반대 방향으로 가까운 순서. 롱은 매물대 윗단, 숏은 아랫단에 닿으면 추가. TP1이 체결된 뒤에는 추가하지 않습니다.
- **손절**: 마지막으로 쓰는 매물대 바깥 0.25 ATR.
- **교차 마진 안전 검사**: 모든 추가가 체결됐다고 가정하고, 증거금이 잔고 안에 들어가고, 손절이 추정 청산가보다 먼저 오고, 손절 시 손실이 잔고의 `DCA_MAX_LOSS_PCT`(기본 30%) 이하가 될 때까지 가장 먼 추가부터 뺍니다.
- 추가될 때마다 평균 진입가와 TP 분할 수량(40/35/25%)을 다시 계산합니다.

### 손절·TP 직접 수정

실매매 화면의 보유 포지션 카드(모의매매를 켠 경우 모의 포지션도 API로)에서 **손절·TP 직접 수정**을 열어 값을 바꾸고 **적용**을 누릅니다.

- 자동 계산(패턴 구조 손절, 매물대 TP)이 기본이고, 직접 수정은 그 위에 덮어씁니다.
- 가격은 거래소 가격 단위로 맞춥니다. 이미 체결된 TP는 잠깁니다.
- 손절이 이미 현재가를 넘었거나 TP가 현재가·진입가보다 수익 방향이 아니면 거부합니다.
- 실주문이 켜져 있으면 거래소 주문도 바꿉니다. 새 손절을 먼저 넣고 기존 손절을 취소하며, 손절을 넓혀 1회 손실 한도(BALANCE: 진입 때 계획한 최대 손실, RISK_USD: `LIVE_MAX_RISK_USD`)를 넘으면 거부합니다. 추매 주문이 남아 있으면 BingX 손절은 포지션 전체 기준으로 겁니다. TP는 기존 주문 취소가 확인된 뒤에만 새로 넣습니다.
- 직접 올린 손절이 진입가보다 유리하면 TP1 이후 자동 본절 이동이 그 손절을 되돌리지 않습니다.


폐기된 공급자·TradFi API 키 설정은 기능에서 참조하지 않습니다. 기존 `.env`에 남아 있더라도 이 업데이트가 파일을 삭제·수정하지 않습니다. 키·토큰을 브라우저·로그·Git에 넣지 마세요.

```text
npm test
node --check server.mjs
npm run test:market
```

`npm test`는 Mock·합성 데이터 기반 회귀 검사입니다. `test:market`(Binance)과 `test:venues`(BingX·Gate.io)는 별도 실제 공개 GET 진단으로 주문·계좌 API를 사용하지 않습니다. 네트워크 정책·거래소 지역 제한이 있으면 실패할 수 있으며 회귀 통과가 실제 연결 성공을 의미하지 않습니다. 두 진단 모두 기존 PNL은 수정하지 않습니다.

실제 과거 캔들·aggTrades·호가와 체결 원장에 기반한 새 전략의 성능 개선, 실제 Windows 기능 및 원격 CI 결과는 해당 검증 자료가 있을 때만 통과로 보고합니다. 이전 단계 문서는 과거 개발 이력이며 현재 활성 기능 안내가 아닙니다.

- **시총 걸러내기**: CoinGecko 시총 상위 2000개(`VENUE_ONLY_MCAP_PAGES` 8쪽 × 250, 6시간마다 갱신)와 티커·가격(±25%)이 맞아야 합니다. 시총 `VENUE_ONLY_MIN_MARKET_CAP_USD`(1000만$) 미만, 시총을 찾을 수 없는 코인, 24h 선물 거래대금이 시총의 `VENUE_ONLY_MAX_VOLUME_TO_MCAP`(5)배를 넘는 코인(거래량 부풀림 의심)은 뺍니다. 시총 자료를 못 받으면 바이낸스 미상장 코인은 추가하지 않습니다.
- 모의매매만 합니다(실주문 제외). 단타(1·5·15분)는 바이낸스 실시간 시세를 쓰므로 대상이 아닙니다. 끄려면 `VENUE_ONLY_COINS=false`.

### 두 PC를 번갈아 쓸 때 (`start_shared.bat`)

`start.bat` 대신 `start_shared.bat`로 켜면 모의매매 **기록**을 OneDrive의 `SignalLabData` 폴더에 두고 두 PC가 같이 씁니다. 텔레그램 토큰·거래소 키가 들어가는 **설정(.env)은 각 PC의 `%LOCALAPPDATA%\SignalLab\.env`에 따로** 둡니다(`SIGNAL_LAB_ENV_DIR`). 예전 버전이 공유 폴더에 복사해 둔 `.env`가 있으면 한 번만 이 PC 설정으로 복사하고, 서버 창에 삭제 권장 안내를 띄웁니다.
- 서버 창과 진단에 이 기록 폴더를 사용한 PC 목록(`pcs.json`)이 나옵니다. 다른 PC 이름이 보이면 OneDrive 동기화가 되고 있는 것입니다.
- OneDrive 충돌 사본(`store-PC이름.json` 등)이 생기면 경고합니다. 지우지 말고 확인하세요. 다른 동기화 폴더를 쓰려면 같은 폴더에 `shared_data_dir.txt`를 만들고 첫 줄에 경로를 적으세요.
- 처음 실행할 때 그 PC의 기존 기록이 공유 폴더로 복사됩니다(공유 폴더에 기록이 없을 때만).
- 한 번에 한 PC만 켭니다. 다른 PC에서 서버가 켜져 있으면(30초마다 갱신되는 잠금, 3분 기준) 실행을 거부합니다.
- 바꿀 때: 쓰던 PC의 서버 창 닫기 → OneDrive 동기화 완료(초록 체크) 확인 → 다른 PC에서 `start_shared.bat`.

### 모의매매 텔레그램 알림 (`PAPER_TRADING=on`일 때만)

텔레그램(`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`)이 설정돼 있으면 모의 **진입·청산**도 휴대폰으로 보냅니다(전략·패턴·점수·진입/손절/목표·차트 거래소, 청산 시 손익·R·사유·보유 시간·누적 손익). 모두 "실제 주문 없음 (모의매매)"로 표시됩니다. 끄려면 `PAPER_TELEGRAM=false`.

### CSV 내려받기 열

기존 열에 더해 `strategy`(HOURLY_1H / SCALP_REVERSAL_1M·5M·15M), `chartVenue`(판단한 차트 거래소), `score`, `sizeScale`(절반 크기 배율), `initialRiskUSD`(진입 시 위험, 물타기는 계획 전체 손절액), `rMultiple`(손익 ÷ 위험), `dcaAddsFilled`, `holdMinutes`가 들어갑니다.

### PC 절전 방지 (Windows)

서버가 켜져 있는 동안 Windows가 절전(대기) 모드로 들어가지 않게 요청합니다. 동영상 재생 프로그램과 같은 방식이라 전원 설정은 바꾸지 않고, 화면은 평소처럼 꺼질 수 있으며, 서버를 닫으면 바로 해제됩니다. 노트북 덮개를 닫을 때의 동작은 Windows 설정을 따릅니다. 끄려면 `KEEP_AWAKE=false`.

### 알림 설정 (켜기·끄기)

`알림 · 시스템` 화면 맨 위 **알림 설정**에서 모든 알림을 켜고 끕니다.
- 서버 알림(모든 화면에 적용, 서버 기록에 저장): 텔레그램 최종 신호 (+ `PAPER_TRADING=on`일 때만 텔레그램·Windows 모의 진입/청산)
- 화면 알림(이 브라우저에만 저장): 신호 팝업, 중요 뉴스 팝업, 알림 소리 (+ 모의매매를 켠 경우 모의 진입/청산 팝업)

### 배율 (10~30배, 1배 단위)

1시간봉 모의 포지션의 배율 = **10배 + 점수 가산 + 시총 가산** (최대 30배).
- 점수 가산: 90점 0 → 91점 +1 → … → 100점 +10 (1점 = 1배)
- 시총 가산(CoinGecko, 6시간마다 갱신): 5천만$ · 1억$ · 2억$ · 5억$ · 10억$ · 20억$ · 50억$ · 100억$ · 300억$ · 1,000억$ 이상마다 각각 +1 (시총 미확인은 0)
- 예: 95점·시총 3억$ → 10+5+3 = 18배 / 100점·BTC → 10+10+10 = 30배
- 크기는 손절 시 손실(위험 한도)로 정하므로 배율은 증거금을 바꾸고 손절 손실은 바꾸지 않습니다. 단타는 점수가 없어 `DCA_LEVERAGE`(10~30)를 씁니다.

### 화면 정리 (2026-11-12)
- TradFi 화면과 BingX·Gate.io 시세 조회 화면을 없앴습니다. 실주문 제어는 `알림 · 시스템` 화면으로 옮겼습니다. (서버의 TradFi 모듈은 이미 꺼져 있고 과거 기록 보존용으로만 남아 있습니다.)
- OpenAI API 키를 설정하면 기사 제목·요약을 문맥에 맞춰 함께 번역하고, 기사를 열 때는 본문 발췌를 문단별로 번역합니다. 키가 없는 경우 설정된 LibreTranslate 또는 Google 공개 번역을 사용합니다. `NEWS_TRANSLATION=off`로 끌 수 있고 번역 실패 시 원문을 보여 줍니다.
- 모의 포지션 카드에 점수와 진입 이유(점수 항목 또는 단타 근거)를 표시합니다.
- 긴 설명은 접어 두고 결과(성과·포지션)를 먼저 보여 줍니다.
