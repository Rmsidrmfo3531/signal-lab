# 클라우드 서버에서 24시간 실행하기

PC를 꺼도 서버가 계속 돌도록 작은 리눅스 클라우드 서버(1GB 메모리)에 설치합니다.

## 1. 서버 만들기 (한 번)
- 지역: **서울** 권장. 미국 지역은 바이낸스가 접속을 막습니다(HTTP 451). 도쿄·싱가포르는 확인되지 않았습니다.
  설치 스크립트가 맨 처음 바이낸스·BingX 접속을 확인하고, 막혀 있으면 설치를 멈춥니다.
- 운영체제: **Ubuntu 24.04 LTS**
- 사양: 1 vCPU · **1GB 메모리** · 25GB 디스크 (512MB는 부족할 수 있습니다)
- 만든 뒤 업체 화면의 **웹 콘솔(Console)** 로 접속합니다 (root).

## 2. 설치 (한 번, 약 5분)
웹 콘솔에서 아래처럼 설치 파일을 만들고 실행합니다(저장소가 비공개라 파일 내용을 붙여 넣습니다).
```
nano install.sh      # deploy/linux/install.sh 내용을 붙여 넣고 저장
bash install.sh
```
`install.sh`는 진행 중에 **공개 키 한 줄**을 보여 줍니다.
GitHub → signal-lab 저장소 → Settings → Deploy keys → Add deploy key 에 붙여 넣고(쓰기 권한 체크 안 함) Enter를 누르면 계속됩니다.

## 3. 키 입력
```
nano /opt/signallab/data/.env
```
PC의 `%LOCALAPPDATA%\SignalLab\.env` 값을 옮겨 적고 저장(Ctrl+O, Enter, Ctrl+X) 후:
```
systemctl restart signal-lab
```

## 4. 화면 보기 (휴대폰·PC 전용 비공개 주소)
```
bash /opt/signallab/app/deploy/linux/tailscale.sh
```
휴대폰·PC에 Tailscale 앱을 설치하고 같은 계정으로 로그인하면 표시된 `https://...ts.net` 주소로 열립니다. 인터넷에 공개되지 않습니다.

## 업데이트
```
bash /opt/signallab/app/deploy/linux/update.sh
```

## 주의
- 클라우드 서버를 켠 뒤에는 **PC 서버를 켜지 마세요** (주문이 두 번 들어갈 수 있습니다).
- 서버가 다시 켜지면 실매매는 비활성으로 시작합니다. 화면에서 **활성화**를 눌러 주세요.
- BingX API 키에 이 서버의 IP만 허용하도록 설정하면 더 안전합니다.

## 급변 알림(공습경보) 수신 (2026-11-24)
카피 수신 서비스(`signal-lab-copy`)가 텔레그램 봇 `@ggangalt2_bot`의 공습경보도 함께 받아 서버로 보냅니다(테스트넷 단타·기록용).
자동 업데이트는 서버(`signal-lab`)만 다시 시작하고 수신 서비스는 다시 시작하지 않으므로, 이 기능이 처음 들어온 뒤 한 번만 아래를 실행합니다.
```
systemctl restart signal-lab-copy
journalctl -u signal-lab-copy -n 20 --no-pager   # "[PUMP] 알림 수신: ggangalt2_bot" 이 보이면 정상
```
다른 채팅을 받으려면 `.env`에 `PUMP_ALERT_CHATS=이름1,이름2`(빈 값이면 끔)를 넣고 같은 명령으로 다시 시작합니다.

## 카피 수신 상태 알림 · 업데이트 후 자동 재시작 (2026-11-24)
수신 서비스(`signal-lab-copy`)가 1분마다 서버에 상태 신호(하트비트)를 보냅니다. 5분 동안 신호가 없거나 텔레그램 연결이 3분 넘게 끊겨 있으면
허용된 텔레그램 채팅으로 **"카피 수신 끊김"** 을 한 번, 돌아오면 **"카피 수신 복구"** 를 한 번 보냅니다(알림만, 주문·설정 변경 없음).
실계좌 화면(#real)에 `카피 수신 OK / 끊김 · 마지막 신호 시각`이 보입니다. 카피 모드가 꺼져 있으면(OFF) 이 기능도 쉽니다.

자동 업데이트로 `copy_listener.py`가 바뀌면 수신 서비스가 1분 안에 알아채고, 전달 중인 메시지가 없을 때(최대 30초 대기, 바쁘면 다음 확인으로 미룸)
스스로 종료합니다. systemd가 `Restart=always`라 약 10초 뒤 새 코드로 다시 시작합니다(새 파일이 문법 검사를 통과하지 못하면 종료하지 않고 지금 버전으로 계속 받음).
다시 시작하는 동안(약 10~20초) 채널에 온 메시지는 시작할 때 채널 기록에서 다시 읽어 순서대로 보냅니다
(마지막으로 보낸 메시지 번호 이후·최근 120초 안·최대 20건, `copy-listener-state.json`; 서버는 같은 메시지 번호를 한 번만 처리합니다).
놓친 메시지 중 120초보다 오래된 것이 있거나 20건을 넘거나 채널 기록을 읽지 못하면 **하나도 다시 보내지 않습니다**
(앞부분이 빠진 채 보내면 모니터 재시작 카드가 새 진입·추매로 처리될 수 있음). 이때 로그에 "다시 보내지 않습니다"가 남으니 채널을 직접 확인합니다.

**이 기능이 처음 들어온 뒤 한 번만** 아래를 실행합니다(지금 돌고 있는 예전 수신 서비스에는 자동 재시작 기능이 없습니다).
```
systemctl restart signal-lab-copy
journalctl -u signal-lab-copy -n 20 --no-pager   # "[COPY] 채널 수신 대기 중 (버전 ...)" 이 보이면 정상
```
설정(`.env`, 보통은 그대로 둡니다): `COPY_CATCHUP_MAX_AGE_SEC`(기본 120, 0이면 다시 읽기 끔), `COPY_HEARTBEAT_SEC`(기본 60), `COPY_SELF_CHECK_SEC`(기본 60).

## 실계좌 증거금 사용률 알림 (2026-11-24)
교차(CROSS) 마진 계좌 전체의 증거금 사용률(BingX 사용 증거금 ÷ 순자산)이 70%·85%·95%를 처음 넘을 때 텔레그램으로 한 번씩 알립니다.
같은 단계는 사용률이 그 단계보다 10%p 아래로 내려가야 다시 알리고, 알림 뒤 가장 낮은 단계(70%) 아래로 내려오면 한 번 알립니다.
메시지에는 사용률·순자산·사용 가능 증거금·미실현 손익·열린 포지션 수가 들어가며 **자동 청산·주문 차단은 없습니다(알림만)**.
단계는 실계좌 화면 "계좌 안전 가드"의 `증거금 사용률 경보` 칸(비우면 끔) 또는 `.env`의 `REAL_MARGIN_ALERT_LEVELS=70,85,95`로 바꿉니다
(화면에서 저장한 값이 `.env`보다 우선). 현재 사용률은 `/status`와 실계좌 화면에 보입니다. `COPY_MODE=LIVE`일 때만 동작합니다.
